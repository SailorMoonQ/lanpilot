# LanPilot 设计文档

- 日期：2026-10-07
- 状态：已评审，待编写实施计划

## 1. 概述

LanPilot 是一个在局域网内用手机遥控电脑的工具。手机端是 iOS / Android App，被控端是常驻在 Windows / Linux 电脑上的后台程序。

### 1.1 目标

- **遥控器**：手机当触摸板、媒体遥控器使用，并能向电脑发送文本
- **快捷指令面板**：手机上一组按钮，触发电脑上预先定义好的动作（锁屏、关机、打开程序、运行脚本等）
- 只在局域网内工作，配对一次之后自动连接
- 一台手机可以控制多台电脑（同一时间连接一台），一台电脑允许多台手机同时连接

### 1.2 非目标

- 不传输电脑屏幕画面（不是远程桌面）
- 不支持跨公网访问
- 不提供"按键模式"的实时键盘（打字只用文本发送模式）
- 暂不支持 macOS 被控端（项目成熟后再加）
- 暂不做按设备区分的权限控制（所有已配对手机权限相同）
- 不用手机音量键控制电脑音量（iOS 没有正规接口）

### 1.3 平台与首个测试环境

| 端 | 平台 | 首个测试环境 |
|---|---|---|
| 手机端 | iOS、Android | iPhone（付费开发者账号，MacBook Pro 编译） |
| 电脑端 | Windows、Linux | Windows 11；Ubuntu 24.04 + GNOME + Wayland |

## 2. 整体架构

### 2.1 仓库结构（单仓库）

```
lanpilot/
├── core/        Rust 共享核心 lanpilot-core：协议、QUIC 传输、身份与配对、mDNS 发现
├── agent/       Rust 常驻进程 lanpilot-agent
├── settings/    Tauri 2 设置窗口 lanpilot-settings（Rust 外壳 + React/TS 前端）
├── app/         Flutter 手机端
│   └── rust/    桥接层，通过 flutter_rust_bridge v2 暴露 core
└── docs/
```

选择单仓库的原因：协议由两端共用，改协议时 `core`、`agent`、`app` 在同一次提交中修改；`agent` 和 `app` 以路径依赖引用 `core`，无需单独发版；CI 可以做跨端集成测试。单仓库不能替代协议版本兼容设计，因为手机端和电脑端是分别发布、分别更新的。

### 2.2 语言与框架

| 部分 | 技术 |
|---|---|
| 共享核心、电脑端常驻进程 | Rust |
| 电脑端设置窗口 | Tauri 2 + React + TypeScript（Windows 用 WebView2，Linux 先用 WebKitGTK） |
| 手机端 | Flutter（Dart），Riverpod，go_router |

### 2.3 core（共享核心）

只包含两端都需要、且必须完全一致的逻辑，不包含任何操作系统相关代码，可以完整编译到 iOS 和 Android：

- 协议消息定义与编解码（Protobuf，`prost`）
- QUIC 传输（`quinn`）：数据报 + 可靠流
- 设备身份（Ed25519 长期密钥、自签名证书、指纹）
- 配对（扫码令牌、SPAKE2 密码配对）
- mDNS 发现（广播与扫描）

### 2.4 电脑端双进程

| | lanpilot-agent | lanpilot-settings |
|---|---|---|
| 运行方式 | 登录后常驻 | 打开设置时启动，关闭即退出 |
| 职责 | 网络服务、输入注入、指令执行、托盘图标；配置文件和设备数据的唯一读写方 | 只负责界面，所有读写通过本地 IPC 交给 agent |
| 依赖 | 不加载 WebView 和界面库 | Tauri + WebView2 / WebKitGTK |

拆分原因：WebView 出问题不影响遥控功能；常驻进程保持最小；配置只有一个写入方，手动编辑、设置窗口、手机同步三种来源不会冲突。

设置窗口前端只通过一层抽象接口（如 `api.getDevices()`）与后端通信，不直接调用 Tauri 接口。若 Linux 上 WebKitGTK 出现无法解决的问题，可以替换外壳（Tauri CEF 运行时或 Electron）而不改前端和 agent。前端只使用成熟的网页特性，开发过程中在 Ubuntu 上实际检查渲染效果。

### 2.5 数据流示例：触摸板移动

```
手指移动 → Flutter 原始触摸事件 → 手势状态机（应用灵敏度、加速度）
        → Rust 核心（QUIC 数据报，加密）→ Wi-Fi
        → agent 的 Rust 核心（解密，验证已配对身份）
        → InputBackend（SendInput / uinput）→ 光标移动
```

## 3. 通信协议

### 3.1 设备发现

- 电脑端通过 mDNS 广播 `_lanpilot._udp.local.`，TXT 记录：
  - `id`：设备公钥指纹前缀
  - `name`：设备名称
  - `os`：`windows` / `linux`
  - `proto`：支持的协议版本范围
- 手机端按 `id` 识别已配对设备，不依赖 IP 地址
- 后备：上次成功连接的地址；手动输入 IP；扫码（二维码内含地址，对已配对设备只更新地址，不重复配对）
- iOS 需在 `Info.plist` 声明 `NSBonjourServices`（`_lanpilot._udp`）和本地网络用途说明，App 内提供权限引导

### 3.2 连接建立

- QUIC over UDP，默认端口 `45810`，可配置；ALPN 为 `lanpilot`
- 双向 TLS 1.3，双方使用由 Ed25519 长期密钥生成的自签名证书，校验方式是对方公钥是否在本地已配对列表中（类似 SSH known_hosts）
- 未配对的连接只能使用配对通道，其余消息一律拒绝
- 禁用 0-RTT（防止快捷指令被重放）
- 支持 QUIC 连接迁移（手机 IP 变化时连接不中断）
- Windows 安装程序添加防火墙规则；Linux 启用 ufw 时由诊断页提示

### 3.3 版本协商

- 连接后首条消息为 `Hello`：协议版本范围、App / agent 版本、能力标志
- 选择共同支持的最高协议版本；无共同版本时，手机端明确提示哪一端需要更新
- 新功能优先用能力标志开关，旧版本不支持的功能在手机端隐藏

### 3.4 消息编码

Protobuf（`prost`）。理由：两端版本经常不一致，Protobuf 支持字段增删，旧版本忽略未知字段。Dart 端不接触编码细节，编解码全部在 Rust 核心完成。每个已发布版本的消息样本保存为黄金样本文件，用于兼容性测试。

### 3.5 通道

**可靠流**（手机打开的一条双向控制流，按顺序、不丢失）：

| 消息 | 说明 |
|---|---|
| `Hello` | 版本与能力协商 |
| `PointerButton` | 鼠标按键按下 / 抬起，带当前手势累计值 |
| `Key` | 单个功能键或组合键 |
| `Text` | 文本发送 |
| `Media` | 播放/暂停、上一首/下一首、音量加减、静音 |
| `RunCommand` → `CommandResult` | 按 ID 执行快捷指令，返回成功、错误或输出 |
| `CommandList` | 电脑端推送指令列表（连接时及配置变化时） |
| `Unpair` | 手机端移除电脑时通知对方 |

请求带 ID，响应回带对应 ID。

**数据报**（不可靠）：只用于鼠标移动和滚动。

### 3.6 鼠标移动：累计值方案

每次手指按下开始一个手势，数据报携带该手势开始以来的累计量：

```
{ 手势ID, 序号, 累计dx, 累计dy, 累计滚动x, 累计滚动y }
```

- agent 记录已应用的累计值，每次只应用差值，丢包后由下一个包自动补齐
- 序号小于已处理序号的包直接丢弃（乱序）
- 累计值为浮点数，agent 保留小数余量，保证慢速移动精度
- 手机端按屏幕刷新率发送（60Hz / 120Hz），同一帧内的触摸事件合并
- 点击消息带当前手势累计值，agent 先补齐位置再执行点击，解决移动与点击乱序问题
- 惯性滚动在手机端计算，同样以累计值发送

### 3.7 断线安全

- 心跳间隔 1 秒，3 秒无响应判定断线
- 断线时 agent 释放该手机按住的所有按键和鼠标按键
- iOS 进入后台时主动断开，回到前台自动重连；监听网络变化，连上 Wi-Fi 后自动重连
- 多台手机的连接和按键状态相互独立

## 4. 配对与安全

### 4.1 设备身份与密钥存储

每台设备首次启动生成 Ed25519 长期密钥，公钥即设备身份。

| 平台 | 私钥存储 |
|---|---|
| iOS | 钥匙串，仅限本设备，不同步 iCloud |
| Android | Android Keystore 密钥加密后保存 |
| Windows | DPAPI 加密（当前用户）；管理员模式下存于 `%ProgramData%` 并限制为管理员可写 |
| Linux | 状态目录中的文件，权限 `0600`（不依赖 GNOME 钥匙环，因其在后台进程场景可能锁定或不存在） |

### 4.2 扫码配对

1. 电脑端显示二维码：IP 地址列表、端口、电脑公钥完整指纹、一次性配对令牌（128 位随机数，有效期 2 分钟，单次使用，过期自动刷新）
2. 手机扫码后连接，先校验电脑证书与二维码中的指纹一致（防冒充）
3. 手机经加密连接发送令牌、自己的公钥、设备名称
4. 电脑校验令牌，双方互存公钥

### 4.3 密码配对

- 默认关闭，在电脑端设置密码后启用；密码最短 6 位
- 手机在设备列表中选择未配对电脑并输入密码
- 使用 SPAKE2，并把双方 TLS 证书公钥绑定进协议：密码不在网络上传输，无法离线暴力破解，中间人会导致验证失败
- 连续失败 5 次后暂停密码配对 5 分钟，并在电脑上通知

### 4.4 配对后管理

- 每次新设备配对成功，电脑上弹出系统通知
- "新设备配对需要在电脑上确认"：默认关闭，可开启
- 电脑端移除设备：立即断开并拒绝后续连接
- 手机端移除电脑：通知电脑双方同时删除；连不上时只删手机端记录
- 配对关系与 IP、网络无关，离开 Wi-Fi 再回来、IP 变化都只需自动重连

### 4.5 其他安全边界

- 快捷指令只能按 ID 触发，手机不能传参，执行内容完全由电脑端配置决定
- 指令以当前登录用户身份运行，不提权
- 本地 IPC 只允许当前用户访问：Windows 命名管道 ACL；Linux socket 位于 `$XDG_RUNTIME_DIR`（`0700`）
- 手机端可选 Face ID 解锁，默认关闭

### 4.6 威胁模型之外

- 攻击者已能以当前用户身份登录电脑
- 手机已解锁、未开启 Face ID 解锁且落入他人手中（补救：电脑端移除该设备）

## 5. 电脑端设计

### 5.1 agent 模块

| 模块 | 职责 |
|---|---|
| server | 用 core 接收连接、认证、分发消息 |
| session | 每台手机一个会话：手势累计值、按住的按键和鼠标按键 |
| input | `InputBackend` 接口 + 平台实现 |
| commands | 内置指令与自定义指令执行 |
| config | 配置读写、文件监听、校验 |
| ipc | 设置窗口的本地 IPC 服务 |
| tray | 托盘图标与菜单（Windows：`tray-icon`；Linux：`ksni`，基于 D-Bus，不依赖 GTK） |
| platform | 开机自启、系统通知、单实例 |

### 5.2 输入注入

```rust
trait InputBackend {
    fn move_relative(&mut self, dx: i32, dy: i32);
    fn button(&mut self, button: MouseButton, down: bool);
    fn scroll(&mut self, dx: f32, dy: f32);
    fn key(&mut self, key: KeyCode, down: bool);
    fn text(&mut self, text: &str);
}
```

协议中的按键统一使用 USB HID 键码，各平台实现时转换。

| | Windows | Linux |
|---|---|---|
| 鼠标、滚动 | `SendInput`，支持细粒度滚轮值 | uinput 虚拟设备 "LanPilot Virtual Input"，`REL_WHEEL_HI_RES` |
| 按键、媒体键 | `SendInput` | uinput `KEY_*` |
| 文本 | `KEYEVENTF_UNICODE` | 待 M0 验证：剪贴板粘贴（完成后恢复原剪贴板）或 IBus 引擎 |

Linux uinput 权限：安装时添加 udev 规则，为 `/dev/uinput` 加 `uaccess` 标签，使当前会话用户获得访问权限。不使用 `input` 组（会开放读取所有键盘输入的权限）。

平台限制：Windows 普通权限下无法操作管理员窗口（UIPI），也无法操作锁屏和登录界面。Linux uinput 在 GNOME 锁屏界面可用。

### 5.3 Windows 管理员模式

- 设置中的开关，默认关闭；打开时弹一次 UAC 确认
- 开启后：开机自启由注册表启动项切换为任务计划程序（"登录时运行、使用最高权限"），开机不弹 UAC
- 快捷指令一律以普通用户身份执行（借助资源管理器的身份启动），管理员权限只用于输入注入。需要管理员权限的脚本自行申请，电脑上正常弹出 UAC
- 本地 IPC 只接受管理员权限的连接；从托盘打开的设置窗口继承 agent 权限，不弹 UAC
- 已配对设备数据迁移到 `%ProgramData%` 并限制为管理员可写，防止普通权限恶意程序借 agent 绕过 UIPI
- 关闭开关时反向迁移

### 5.4 快捷指令

**内置指令**（可单独启用或关闭）：

| 指令 | Windows | Linux（GNOME） |
|---|---|---|
| 锁屏 | `LockWorkStation` | `loginctl lock-session` |
| 睡眠 | `SetSuspendState` | `systemctl suspend` |
| 关机 / 重启（默认需确认） | 系统关机 API | `systemctl poweroff` / `reboot` |
| 显示桌面 | `Win+D` | `Super+D` |
| 媒体、音量、静音 | 媒体键 | 媒体键 |

**自定义指令类型**：打开程序（路径、固定参数、工作目录）、打开网址、打开文件或文件夹（`ShellExecute` / `xdg-open`）、发送组合键、运行命令或脚本（cmd / PowerShell / bash；"不等待"或"等待完成"，后者有超时，返回退出码和最多 1 KB 输出）。每条指令可设置执行前在手机上确认。

### 5.5 配置

- 配置文件：Windows `%APPDATA%\LanPilot\config.toml`；Linux `~/.config/lanpilot/config.toml`
- 已配对设备和密钥单独存放在状态目录，不放入配置文件
- 指令使用稳定 ID，改名或改图标不影响手机端布局
- 文件变化自动重新加载并推送给已连接手机；配置有误时继续使用旧配置，在设置窗口显示错误位置并通知
- 原子写入（临时文件 + 替换）

```toml
[general]
name = "书房台式机"
port = 45810
autostart = true

[pairing]
password_enabled = false
require_confirmation = false

[builtin]
shutdown = { enabled = true, confirm = true }
sleep = { enabled = true }

[[commands]]
id = "open-vscode"
name = "打开 VS Code"
icon = "code"
type = "program"
path = "C:\\Program Files\\Microsoft VS Code\\Code.exe"

[[commands]]
id = "backup"
name = "备份照片"
icon = "cloud-upload"
type = "script"
shell = "powershell"
script = "robocopy D:\\Photos E:\\Backup /MIR"
wait = true
timeout_secs = 600
confirm = true
```

### 5.6 托盘菜单

```
LanPilot - 已连接 N 台设备
配对新设备...
设置...
暂停遥控（拒绝输入但保持连接）
退出
```

### 5.7 开机自启与安装包

- Windows：当前用户注册表启动项（管理员模式下为任务计划程序）；MSI 或 NSIS 安装程序，包含两个程序和防火墙规则
- Linux：XDG 自启动 `~/.config/autostart/lanpilot.desktop`；先提供 .deb，安装时写入 udev 规则并立即生效（AppImage 无法安装 udev 规则，暂不提供）
- 日志滚动写入文件，可在设置窗口查看

### 5.8 设置窗口

页面：概览、设备（配对、已配对列表）、快捷指令（内置 + 自定义，新增、编辑、排序、测试运行）、通用设置（含管理员模式）、诊断（uinput 权限、端口、防火墙、日志）。

IPC 接口（请求 / 响应 + 事件推送）：读取状态、读写配置、开始配对（返回二维码内容）、设置密码、移除或重命名设备、运行诊断、订阅事件（设备上下线、配对请求）。

## 6. 手机端设计

### 6.1 页面结构

```
设备列表（首页）：已配对电脑（在线/离线）、发现的新电脑、扫码配对、设置
控制页：顶部电脑名称（可切换）与连接状态；标签 [触摸板] [快捷指令] [媒体]；
        触摸板页的键盘按钮打开文本发送面板
```

同一时间只连接一台电脑，切换时先断开当前连接。横竖屏都支持：横屏时触摸板占满屏幕，标签栏移到侧边。

### 6.2 触摸板手势

| 手势 | 操作 |
|---|---|
| 单指滑动 | 移动光标 |
| 单指轻点 | 左键单击 |
| 双指轻点 | 右键单击 |
| 双指滑动 | 滚动（松手后惯性滚动） |
| 轻点后立即按住滑动 | 拖动 |
| 三指轻点 | 中键单击 |
| 双指捏合 | 缩放（`Ctrl + 滚轮`） |

- 可选的左右键按钮条；点击振动反馈；触摸板页面保持屏幕常亮
- 直接处理原始触摸事件，手势识别为独立的纯 Dart 状态机

### 6.3 快捷指令面板

按钮网格，支持分组；编辑模式下可拖动排序、移动分组、隐藏、改颜色。布局按"电脑 ID + 指令 ID"保存在本地，新指令自动进入"未分组"，已删除指令自动消失。需要确认的指令先弹确认框；结果以提示显示，失败显示原因，"等待完成"的指令可查看输出。

### 6.4 媒体页与文本发送

- 媒体页：播放/暂停、上一首、下一首、音量加减、静音
- 文本发送面板：输入框（支持系统输入法、语音输入）、发送按钮、功能键（回车、退格、Esc、Tab、方向键）

### 6.5 设置

触摸板灵敏度、加速度曲线、滚动速度、自然滚动、振动反馈、按键条显示、主题（跟随系统 / 浅色 / 深色）、Face ID 解锁、语言（中文、英文，默认跟随系统）。

### 6.6 技术实现

- Rust 桥接接口：`discover()`（设备流）、`pairWithQr()`、`pairWithPassword()`、`connect(deviceId)` 返回会话对象（`sendPointer()`、`sendButton()`、`sendKey()`、`sendText()`、`sendMedia()`、`runCommand()`，连接状态流、指令列表流）
- 本地存储：设置和布局用 JSON 文件，外加存储接口；密钥在钥匙串
- 权限：本地网络、相机、Face ID（可选）

### 6.7 连接状态

顶部显示连接中 / 已连接 / 重新连接中；断线时触摸板显示半透明遮罩和"正在重新连接"；版本不兼容时提示需要更新哪一端。

## 7. 测试与质量

- **core**：协议黄金样本兼容性测试；配对安全测试（中间人、令牌过期与重用、密码错误、限速）；鼠标累计值属性测试（随机丢包、乱序后最终位置一致）
- **agent**：使用记录型模拟 `InputBackend` 的集成测试，用 Rust 测试客户端走完整流程（配对、连接、移动、点击、指令、断线后按键释放）；网络异常测试（丢包、乱序、延迟、重连）；Linux 上创建真实 uinput 设备并用 evdev 读回验证
- **mock agent**：使用模拟输入实现，可在 macOS 上运行，用于手机端开发与集成测试
- **手机端**：手势状态机单元测试；组件测试与截图对比（横竖屏、深浅色、中英文）；iOS 模拟器连接 mock agent 的集成测试
- **真机端到端**：每个里程碑结束时用 iPhone + Ubuntu + Windows 按检查清单测试；调试模式显示实时往返延迟
- **代码规范**：Rust `clippy`（警告即错误）与 `rustfmt`；Dart `dart analyze` 与 `dart format`；TS 严格模式、ESLint、Prettier
- **CI**：GitHub Actions，Linux / Windows / macOS，按改动目录触发；不稳定的测试必须修复，不允许跳过

## 10. 决策记录

| 决策 | 选择 | 主要理由 |
|---|---|---|
| 手机端形态 | 原生体验 App（非 PWA） | 自动发现、触控手感、振动、后台行为 |
| 手机端框架 | Flutter | 自定义控件为主，跨平台表现一致 |
| 电脑端语言 | Rust | 常驻进程体积、性能、系统调用、跨平台 |
| Linux 输入 | uinput | X11 / Wayland / 各桌面环境通用 |
| 通信 | 共享 Rust 核心 + QUIC | 数据报解决 Wi-Fi 丢包卡顿；安全代码只写一份 |
| 编码 | Protobuf | 两端版本不一致时的前后兼容 |
| 配对 | 扫码 + 可选密码（SPAKE2） | 安全且免每次输入；密码不可离线破解 |
| 快捷指令 | 电脑端定义白名单，手机端管理布局 | 执行内容由电脑决定，安全边界清晰 |
| 电脑端配置 | TOML 文件 + 图形设置窗口 | 日常用界面，备份迁移用文件 |
| 设置窗口 | Tauri 2 + React，Linux 先用 WebKitGTK | 网页技术开发效率；保留替换外壳的余地 |
| 电脑端进程 | agent 与设置窗口分离 | 常驻进程最小化，界面故障不影响遥控 |
| 文本输入 | 只做文本发送模式 | 用户几乎不需要实时按键输入 |
